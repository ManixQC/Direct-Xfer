# Direct-Xfer 1.66.5 — Windows portable

`Direct-Xfer.exe` is the .NET 10 (`net10.0-windows`) WinForms tray/launcher UI. `Direct-Xfer.ServerHost.exe` is the .NET 10 Windows host that supervises the pinned Node.js runtime and the Direct-Xfer backend. Both executables are published **framework-dependent single-file for win-x64** and use the same private shared .NET runtime under `runtime/dotnet`.

The default portable package generated by GitHub Actions contains:
- `Direct-Xfer.exe`
- `Direct-Xfer.ServerHost.exe`
- `runtime/app` — Direct-Xfer 1.66.5 application runtime
- `runtime/node/node.exe` — pinned official x64 Node.js runtime
- `runtime/dotnet` — one private shared .NET 10 runtime tree used by both Windows EXEs (base Runtime + WindowsDesktop framework)

**rclone and Tesseract are deliberately not included in the default Windows package or installer.** This keeps the base installer substantially smaller. They are downloaded only after the current user explicitly activates the corresponding optional component from the Direct-Xfer system-tray menu.

Direct-Xfer bundles **one private .NET 10 runtime tree x64** under `runtime\dotnet`. GitHub Actions assembles that tree by merging Microsoft's matching `dotnet-runtime` archive (host + `Microsoft.NETCore.App`) with the `windowsdesktop-runtime` archive (`Microsoft.WindowsDesktop.App`). Both `Direct-Xfer.exe` and `Direct-Xfer.ServerHost.exe` resolve this app-relative runtime through `AppHostDotNetSearch=AppRelative`, so the runtime is stored once instead of being duplicated inside both EXEs. **No separate Microsoft .NET Runtime or Desktop Runtime installation is required on Windows.**

The application is intentionally unsigned. Runtime state is stored under `%LOCALAPPDATA%\Direct-Xfer` and the folders selected during first-run setup.

## Optional components

Right-click the Direct-Xfer icon in the Windows system tray and open **Optional components / Composants optionnels**. Each component is downloaded only after an explicit confirmation:

- **rclone 1.74.4** → `%LOCALAPPDATA%\Direct-Xfer\tools\rclone\1.74.4\rclone.exe`
- **Tesseract OCR 5.5.3** → `%LOCALAPPDATA%\Direct-Xfer\tools\tesseract\5.5.3\`

Activating or removing a component signals ServerHost to reload automatically; the main Direct-Xfer installer does not need to be run again. The menu also provides a remove/deactivate action that deletes the per-user optional component.

The rclone archive and Tesseract setup executable are pinned to Direct-Xfer's expected versions and SHA-256 hashes before installation. The `eng`, `fra` and `spa` OCR models are fetched from a pinned immutable `tessdata_fast` commit and validated before activation.

## Storage connectors on Windows

rclone is optional on Windows. Activate it from **system tray → Optional components → Activate rclone** before using Direct-Xfer's rclone-backed storage connectors when no compatible `rclone` is already supplied through `RCLONE_BIN`/`PATH`.

Direct-Xfer keeps its rclone configuration under `%LOCALAPPDATA%\Direct-Xfer\data\rclone\rclone.conf`. Explicit `RCLONE_BIN` and `RCLONE_CONFIG` environment overrides always take precedence over the optional component.

After activation, the per-user rclone configuration can also be edited manually from PowerShell:

```powershell
& "$env:LOCALAPPDATA\Direct-Xfer\tools\rclone\1.74.4\rclone.exe" config --config "$env:LOCALAPPDATA\Direct-Xfer\data\rclone\rclone.conf"
```

## OCR / Tesseract

Tesseract is optional on Windows. In the normal Windows-hosted configuration, server-side OCR remains disabled while the optional Tesseract component is absent. Activate it from **system tray → Optional components → Activate Tesseract OCR**; Direct-Xfer then downloads Tesseract 5.5.3 plus the `eng`, `fra` and `spa` models into the current user's Direct-Xfer tools directory and reloads ServerHost.

Explicit `SEARCH_OCR_ENABLED`, `SEARCH_OCR_TESSERACT_BIN` and `TESSDATA_PREFIX` administrator overrides are preserved. A manually supplied/system Tesseract can therefore still be used without downloading the Direct-Xfer optional component. If the optional component cannot satisfy the requested `SEARCH_OCR_LANGS`, ServerHost does not silently run the incomplete private engine.

Scanned-PDF OCR additionally requires Poppler (`pdftoppm`); searchable PDFs can still use their embedded text layer without Poppler.

## Windows payload size optimization

The Windows build creates a dedicated production-only `node_modules` tree with `npm ci --omit=dev` and removes only development metadata (tests, examples, documentation, source maps and TypeScript declarations) while retaining licenses and runtime assets. GitHub Actions enforces the `node_modules` size budget and also fails if `runtime\rclone` or `runtime\tesseract` accidentally reappears in the default package. Optional component bytes are therefore completely outside the base installer.
