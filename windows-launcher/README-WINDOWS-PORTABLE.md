# Direct-Xfer 1.69.4 — Windows portable

`Direct-Xfer.exe` is the .NET 10 (`net10.0-windows`) native Win32 tray/launcher UI. `Direct-Xfer.ServerHost.exe` is the .NET 10 Windows host that supervises the pinned Node.js runtime and the Direct-Xfer backend. Both executables are published **framework-dependent single-file for win-x64** and use the same private shared .NET runtime under `runtime/dotnet`.

The default portable package generated by GitHub Actions contains:
- `Direct-Xfer.exe`
- `Direct-Xfer.ServerHost.exe`
- `runtime/app` — Direct-Xfer 1.69.4 application runtime
- `runtime/dotnet` — one private shared .NET 10 runtime tree used by both Windows EXEs (base Microsoft.NETCore.App runtime only)
- `runtime/node/node.exe` — pinned Node.js 24.19.0 x64 runtime, bundled and integrity-checked by CI

**Node.js 24.19.0 x64 is bundled in the default Windows package under `runtime/node/node.exe`.** GitHub Actions downloads the pinned executable, verifies SHA-256 `3602f2bb1a10f2cbab4c36886218a33c1ab3db87290e73b033c46c77147d0237` and its exact version, then packages it. The installer itself performs no Node.js download. **rclone and Tesseract remain deliberately excluded from the default package and installer** and are downloaded only after explicit activation from the system-tray menu.

Direct-Xfer bundles **one private .NET 10 runtime tree x64** under `runtime\dotnet`. GitHub Actions builds that tree from Microsoft's matching `dotnet-runtime` archive (host + `Microsoft.NETCore.App`) only. The launcher uses native Win32 APIs and does not require `Microsoft.WindowsDesktop.App`. Both `Direct-Xfer.exe` and `Direct-Xfer.ServerHost.exe` resolve this app-relative runtime through `AppHostDotNetSearch=AppRelative`, so the runtime is stored once instead of being duplicated inside both EXEs. **No separate Microsoft .NET Runtime or Desktop Runtime installation is required on Windows.** `Microsoft.WindowsDesktop.App` is not bundled.

## Code signing policy

Release builds can be Authenticode-signed through **SignPath Foundation Open Source Code Signing**. Free code signing provided by [SignPath.io](https://about.signpath.io/), certificate by [SignPath Foundation](https://signpath.org/). The GitHub Actions release path signs `Direct-Xfer.exe` and `Direct-Xfer.ServerHost.exe` first, rebuilds the installer with those signed binaries, then signs the final installer and verifies all three signatures before publication. Regular push/development artifacts remain unsigned unless the manual workflow is explicitly run with SignPath signing enabled. See the repository `CODE_SIGNING_POLICY.md` for the complete policy.

Runtime state is stored under `%LOCALAPPDATA%\Direct-Xfer` and the folders selected during first-run setup.

The Inno Setup installer displays the repository privacy policy before installation. Its task page explicitly lets the user choose Windows autostart, automatic update checks, and startup public-IP discovery. Those network choices are applied to Direct-Xfer settings on the first server launch after install/upgrade and can be changed later from the admin interface. Uninstall from **Windows Settings → Apps → Installed apps → Direct-Xfer**.

## Optional components

Right-click the Direct-Xfer icon in the Windows system tray and open **Optional components / Composants optionnels**. Each component is downloaded only after an explicit confirmation:

- **rclone 1.75.0** → `%LOCALAPPDATA%\Direct-Xfer\tools\rclone\1.75.0\rclone.exe`
- **Tesseract OCR 5.5.3** → `%LOCALAPPDATA%\Direct-Xfer\tools\tesseract\5.5.3\`

Activating or removing a component signals ServerHost to reload automatically; the main Direct-Xfer installer does not need to be run again. The menu also provides a remove/deactivate action that deletes the per-user optional component.

The rclone archive and Tesseract setup executable are pinned to Direct-Xfer's expected versions and SHA-256 hashes before installation. The `eng`, `fra` and `spa` OCR models are fetched from a pinned immutable `tessdata_fast` commit and validated before activation.

## Storage connectors on Windows

rclone is optional on Windows. Activate it from **system tray → Optional components → Activate rclone** before using Direct-Xfer's rclone-backed storage connectors when no compatible `rclone` is already supplied through `RCLONE_BIN`/`PATH`.

Direct-Xfer keeps its rclone configuration under `%LOCALAPPDATA%\Direct-Xfer\data\rclone\rclone.conf`. Explicit `RCLONE_BIN` and `RCLONE_CONFIG` environment overrides always take precedence over the optional component.

After activation, the per-user rclone configuration can also be edited manually from PowerShell:

```powershell
& "$env:LOCALAPPDATA\Direct-Xfer\tools\rclone\1.75.0\rclone.exe" config --config "$env:LOCALAPPDATA\Direct-Xfer\data\rclone\rclone.conf"
```

## OCR / Tesseract

Tesseract is optional on Windows. In the normal Windows-hosted configuration, server-side OCR remains disabled while the optional Tesseract component is absent. Activate it from **system tray → Optional components → Activate Tesseract OCR**; Direct-Xfer then downloads Tesseract 5.5.3 plus the `eng`, `fra` and `spa` models into the current user's Direct-Xfer tools directory and reloads ServerHost.

Explicit `SEARCH_OCR_ENABLED`, `SEARCH_OCR_TESSERACT_BIN` and `TESSDATA_PREFIX` administrator overrides are preserved. A manually supplied/system Tesseract can therefore still be used without downloading the Direct-Xfer optional component. If the optional component cannot satisfy the requested `SEARCH_OCR_LANGS`, ServerHost does not silently run the incomplete private engine.

Scanned-PDF OCR additionally requires Poppler (`pdftoppm`); searchable PDFs can still use their embedded text layer without Poppler.

## Node.js installation model

The GitHub Actions payload contains the pinned `runtime/node/node.exe` by default. For 1.69.4, Node.js is therefore available immediately after installation without searching PATH, the registry, or the network. Setup validates the installed file as an x64 executable, confirms the exact pinned version and SHA-256, and probes it with the original user's token before ServerHost is started. A legacy `external-node.ini` receipt from the former on-demand architecture is removed during upgrade and is no longer generated by Setup.

ServerHost still supports `DX_WINDOWS_NODE` + `DX_WINDOWS_NODE_SHA256` as a guarded emergency/manual fallback if the bundled private Node runtime is deliberately removed or unavailable, but the normal installed path always uses the bundled pinned runtime.

## Windows payload size optimization

The Windows build creates a dedicated production-only `node_modules` tree with `npm ci --omit=dev` and removes only development metadata (tests, examples, documentation, source maps and TypeScript declarations) while retaining licenses and runtime assets. GitHub Actions enforces the `node_modules` size budget, requires the exact pinned `runtime\node\node.exe`, and fails if `runtime\rclone` or `runtime\tesseract` accidentally appears in the default package. Node.js is therefore part of the installer payload again, while rclone and Tesseract remain optional.
